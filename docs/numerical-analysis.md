# 残酷育儿模拟器 · 数值拟合与优化建议

> 基于策划文档与源码的深度数值分析，2026-06-01

---

## 一、时间模型

```
1 实际秒 = 2 游戏分钟 (1x 速)
1 游戏天 = 720 实际秒 = 12 实际分钟
  ├── 白天 (06:00-20:00) = 420 实际秒 (7 分钟)
  └── 夜间 (20:00-06:00) = 300 实际秒 (5 分钟)
```

---

## 二、属性衰减-恢复拟合

将每游戏天的总衰减量（含白天+夜间倍率）与最大可恢复量做对比。

### 2.1 饱腹度 ⚠️ 高压

```
衰减/天    = 1.3×420 + 1.3×1.35×300 = 1,072.5

喂奶恢复   = 22 + feedBonus
  低档 27  → 需 40 次喂奶/天 (占行动预算 39%)
  中档 32  → 需 34 次喂奶/天 (占行动预算 33%)
  高档 37  → 需 29 次喂奶/天 (占行动预算 28%)

理论上限: 720s/7s(CD) = 103 次/天，够用但饱和

父母精力消耗: 喂奶 6 精/次 × 40 次 = 240 精/天
单职工预算: 120(上限) + 0.9×1.2×420(白天恢复) = 573.6 ✓
双职工预算:  80(上限) + 0.9×0.8×420(白天恢复) = 382.4 ⚠️
```

**结论**: 饥饿管理吃掉行动预算的三分之一，双职工家庭精力紧张但勉强可撑。这是游戏中最大的"操作税"。

---

### 2.2 精力值（婴儿）🔴 数学崩溃

```
衰减/天    = 0.9 × (420 + 300×1.35) = 742.5

哄睡恢复   = +5
最大哄睡   = 720s/10s(CD) = 72 次/天
最大恢复   = 72 × 5 = 360 ← 仅有衰减的 48%！

单个 CD 周期 (10s):
  衰减: 0.9×10 = 9 (白天), 0.9×1.35×10 = 12.15 (夜间)
  恢复: +5
  净效果: -4 ~ -7.15 ← 每周期都是负收益！
```

**这是整个数值系统中最严重的缺陷**。婴儿精力值在数学上**不可能被任何操作维持**，即使玩家卡 CD 完美操作，精力值也会持续下跌并最终锁定在 0。

- 从初始 78 降到 0 仅需 ~200 秒（约 3 分钟）
- 降为 0 后持续触发"精力 < 18 → 哭泣"条件
- 哭泣又驱动父母情绪衰减和健康衰减，形成**不可逆的连锁崩盘**
- 胀气睡眠期的 +0.55 额外衰减堆在一个本就无法维持的属性上，纯属**无效加压**

> 💡 **建议**：将哄睡的能量恢复从 +5 提高至 **+18~22**（或等效地将基础精力衰减从 0.9 降至 0.25），使单属性可被专注维持。同时让其他属性的操作占用形成自然制约。

---

### 2.3 舒适度 ✅ 最健康

```
衰减/天 (低档消耗品): 0.7 × 825 = 577.5
衰减/天 (中档消耗品): 0.4 × 825 = 330
衰减/天 (高档消耗品): 0.2 × 825 = 165

恢复手段（多源组合）:
  换尿布 +18 (CD 3s)  哄睡 +28 (CD 10s)  拍嗝 +10 (CD 2.5s)
  抚触 +9  (CD 6s)   洗澡 +14 (CD 13s)

最高单源理论恢复: 240次/天×18 = 4,320 → 远超衰减
```

**结论**: 舒适度多源恢复设计优秀，采购档次对舒适度的影响放大明显（低档衰减是高档的 3.5 倍），驱动玩家追求升级。

---

### 2.4 安全感 🟡 有隐患

```
衰减/天    = 0.5 × 825 = 412.5

恢复手段:
  陪玩 +11 (CD 5s, 最大 144次/天, 最大恢复 1,584)
  轻拍安抚 +2.2/次 (无 CD！可无限点击)
  抚触 +4 (CD 6s)
```

**结论**: 数值合理，但"轻拍安抚无 CD"使安全感近乎不会崩 —— 玩家可无限点击刷安全感。这削弱了"残酷"主题。

> 💡 **建议**：给轻拍安抚加上 1-2 秒内置 CD，或限制每日使用次数（如 30 次/天），增加其作为"紧急手段"而非"无限刷"的定位。

---

### 2.5 健康值 ✅ 设计优秀

```
仅在以下情况衰减:
  - 四属性均值 < 22 → 每秒 -2.1
  - 忽略哭泣 > 18秒 → 每秒 -2.5
```

**结论**: 二级衰减机制是优秀设计 —— 健康是"结果指标"，玩家管理好前四个属性则健康稳定，管理不好则加速死亡。

### 问题诊断

| 问题 | 严重度 | 说明 |

| 难度扁平化 | 🟡 中 | 加权分 3.65~4.05，离散度仅 11%，各阶段体感雷同 |

| 胀气期无效加压 | 🟡 中 | 精力 +0.55 加在已崩溃的属性上，不产生有意义的选择压力 |

| 缺少难度递增 | 🔴 高 | 游戏中后期反而没有比前期更难的全局压力（如基础倍率递增） |

## 五、事件系统分析

### 5.1 选项设计评估

以"脐带红肿"为例，三个选项的决策空间：

```
选项A 正确  : ¥0，健康 +2        → 免费小收益，知情玩家的最优选
选项B 付费  : ¥200×折扣，健康 +4 → 高档医疗时 ¥0，中档 ¥140
选项C 错误  : ¥0，健康 -4        → 惩罚性选项，纯负收益

收益差: A vs C = 6 点健康 / A vs B = 2 点健康差
```

**评估**: 三选项结构合理，符合"正确答案 / 付费捷径 / 错误陷阱"的设计模式。高档医疗保险使付费选项免费化，存在良好的采购联动。

### 5.2 事件频率问题 🔴

```
每日排队: 每昼夜切换 × 1~3 个随机事件 = 日均约 4 个
全年事件: 365 × 4 = 约 1,460 个事件

每阶段池仅有 2 个事件!
  新生儿期(30天)  ≈ 120 次事件 → "脐带红肿""吐奶呛奶"各 ~60 次
  胀气期(91天)    ≈ 364 次事件 → 重复 182 次
```

**结论**: 事件严重不足，玩 30 分钟就会看到"脐带红肿"弹出 60 次，重复感极强。

> 💡 **建议**: (1) 每阶段池扩展到 6-8 个事件；(2) 添加"已见事件冷却"机制，同一事件一定天数内不重复；(3) 引入稀有事件和小概率惊喜事件。

### 5.3 事件队列积压

```
极端情况: 玩家连续跳过 3 天，事件队列积压 12 个事件
解除方式: 逐个弹出，无法跳过，强制一个个处理
```

> 💡 **建议**: 允许玩家"批量处理"积压事件（如选择"全部采用保守方案"），避免从暂停返回后被事件淹没。

## 六、操作时间占比分析

以 1x 速下维持婴儿不哭泣为目标，计算各项操作的理想时间占比：

```
操作      单位恢复    CD      理想频率      时间占比      精力成本/天
─────────────────────────────────────────────────────────────────
喂奶      饥饿+27     7s      每~20s一次     35%          240
换尿布    舒适+18     3s      每~15s一次     20%          144
哄睡      精力+5     10s      全力也无法维持   —           360
陪玩      安全+11     5s      每~25s一次     20%          201
拍嗝      舒适+10   2.5s      按需(~备选)    5%            58
抚触      舒适+9     6s      按需(~备选)    7%            69
洗澡      健康+14   13s      按需(~备选)    4%            55
休息      父母恢复   18s      按需           5%           -216(恢复)
```

**核心发现**: 总操作时间占比超过 100%，印证了游戏的核心设计理念 —— **玩家永远无法兼顾所有属性，必须在不同需求之间做艰难取舍（Triage）**。这不是 bug，而是"残酷"主题的核心体验。

## 七、变速系统的乘数效应

```
速度    游戏天/实际分钟    饥饿操作频率    单日实际时长
──────────────────────────────────────────────────────
0.2x     0.17              每100秒一次    60分钟/天
0.5x     0.42              每40秒一次     24分钟/天
1.0x     0.83              每20秒一次     12分钟/天
2.0x     1.67              每10秒一次      6分钟/天
4.0x     3.33              每5秒一次       3分钟/天
```

**4x 速分析**：3 分钟过一个游戏天，需要每 5 秒点一次喂奶，同时管理 5 个其他属性。这基本要求 **~50 有效 APM**，接近 RTS 游戏的微操强度。

> 💡 **建议**: 4x 速可在 30 分钟内通关全年（3 分钟 × 365 天），建议在 4x 速下为操作加入少量自动执行或缓冲，使其保持可控。

## 八、综合优化建议汇总

### 🔴 高优先级

| # | 建议 | 原因 |
|---|------|------|
| 1 | **修复精力值崩溃** | 哄睡 +5 vs 衰减 0.9/s = 数学上无法维持。建议哄睡恢复提至 +18~22 或衰减降至 0.25 |
| 2 | **扩展事件池** | 每池 2 个事件导致极高重复。建议每池 6-8 个 + 已见冷却 |
| 3 | **学步期喂奶困境** | 饥饿 1.7 + ×0.5 形成 3.4 倍等效压力，需增加该阶段专用交互（如"花样辅食"额外恢复） |

### 🟡 中优先级

| # | 建议 | 原因 |
|---|------|------|
| 4 | **轻拍安抚加 CD** | 无 CD 使安全感近乎无限，建议 1-2s 内置 CD 或每日 30 次上限 |
| 5 | **阶段难度梯度化** | 加权分 3.65~4.05 过于平坦，建议引入全局衰减倍率随月龄递增 (1.0→1.3) |
| 6 | **中档生存线调整** | ¥50,000+全中档在 306 天资金见底，建议微调让恰好撑到 365 天 |
| 7 | **阶段持续时间延长** | 当前 4-8 天太短，建议拉长至 8-15 天，配合更多阶段专属事件 |

### 🟢 低优先级

| # | 建议 | 原因 |
|---|------|------|
| 8 | **加入中期升级** | 允许在游戏中动态提升采购档次（如第 180 天"换更好的奶粉"） |
| 9 | **稀有事件系统** | 加入低概率触发的惊喜事件（如"宝宝第一次笑"），提供积极反馈 |
| 10 | **事件批量处理** | 暂停/加速后事件积压时提供"批量保守处理"选项 |
| 11 | **高档采购降价** | 适当降低高档全选门槛（当前 ¥119,000），让 ¥100,000 收入可触及 |
| 12 | **4x 速辅助** | 高速模式下为关键操作添加微弱自动执行，保持高压但不失控 |
